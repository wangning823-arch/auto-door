## 1. 315 学习被噪音抢先判成功

### 现象
点「学习」后尚未按遥控就显示「学习成功」；学到的码发射打不开门。

### 根因
- ISR 在凑够约 15 个数据脉冲后，遇 8ms 帧间隙即提前结束抓包
- 提帧只要 ≥10 脉冲就过，噪音易被存成固定码
- 工具侧对串口残留的「学习成功」无过滤

### 修复（固件 `rf_capture.cpp` / `rf_capture.h`）
- `capture(..., warmupMs, learnMode)`：学习模式预热 **500ms** 丢弃起振噪声
- 学习模式禁止 ISR 提前收尾；最短监听 **2s** + 静默 **40ms**
- 数据脉冲门槛学习时 **≥24**；`extractOneFrame` 有效帧 **≥24**
- `frameLooksLikeFixedCode()`：脉宽范围 + 短/长双峰 + 可选重复周期

### 修复（工具）
- `rf_learn_gui.py`：发 `rflearn` 前清缓冲；**1.2s 内的「学习成功」忽略**；识别新失败文案
- `rf_learn_guide.py` / `_rflearn_wait.py`：同样过滤过早成功

## 3. BLE 自动开关门

### 3.1 阻塞扫描导致状态机不跑
`runScan()` 同步阻塞，`busy_` 边沿在同一轮 `trackPoll` 内完成，原先靠跨轮 busy 判断永不触发。  
**修复**：用 `lastScanEndMs()` 变化判断「本轮扫描刚结束」再评估状态机（`ble_scan.h` 暴露 getter）。

### 3.2 自动开被门磁挡住
关门后门磁常立刻报 OPEN（无门磁/极性/行程中），`canAutoOpenNow()` 因 `doorState_==OPEN` 静默拒绝。  
**修复**：
- 自动开**不依赖门磁**，只保留 hold + 5min 开冷却
- 自动开/关被拒时打日志
- 自动关后 **20s** 内忽略门磁「仍开着」

### 3.3 无→有即开（门关信号弱）
原先必须 **无→弱→强(-80)** 才开；铁门挡住时门口约 **-93**，进不了强，要等门缝开。  
**新规则（BLE）**：
- **无 → 有即开**（≥ -110 即算有，弱信号也开）
- **首见 ≥ -70**（`RSSI_SUDDEN_STRONG`）不开 → 库内蓝牙唤醒
- **强(-80) → 弱 → 无 = 关**
- 有信号又消失且未进库变强 → 尝试关（受 hold/冷却保护）

## 4. 经典蓝牙与 BLE 统一

原先经典为：`GRADUAL_IN && rssi≥-80` 才开，渐离后再等约 100s 清空才关。  
**现与 BLE 同一套状态机**（`main.cpp` Classic 分支）：
- 同样无→有开 / 首见≥-70 不开 / 强→弱→无关
- 有信号窗口 `BLE_SILENT_GAP_MS`（15s），适配 Inquiry ~3s 一轮
- 日志：`[CLASSIC] rssi=... phase=...`，跳变 `[FSM] C ...`

网页提示已改为 BLE/经典同一套说明。

## 5. 关键阈值（`config.h`）

| 宏 | 值 | 含义 |
|----|-----|------|
| `RSSI_APPEAR_MIN` | -110 | 有信号下限 |
| `RSSI_STRONG` | -80 | 强信号（关门路径） |
| `RSSI_SUDDEN_STRONG` | -70 | 首见就 ≥ 此值不自动开 |
| `BLE_SILENT_GAP_MS` | 15000 | 多久算无信号 |
| `AUTO_COOLDOWN_OPEN_MS` | 300000 | 开门冷却 5min |
| `AUTO_COOLDOWN_CLOSE_MS` | 30000 | 关门冷却 30s |
| `AUTO_MIN_OPEN_HOLD_MS` | 60000 | 开后至少保持 60s |

## 7. 第二块 ESP32 问题（2026-09-19，已改代码未烧录）

### 现象
1. 上电后不断发关门指令  
2. 开门指令不正确  

### 根因
1. **连发 close**：状态机在「库内唤醒强跳变 → 询问丢包 → STRONG+lost」或「出现又立刻丢失」时反复 `tryAutoClose`；门磁若一直报 OPEN，`canAutoClose` 每 30s 冷却后又能再发。经典模式还曾在 **每个 loop** 评估。  
2. **开码不对**：第二板 NVS 的 key0 可能仍是历史「开=关码拷贝」或空；未编入已验证 49 脉冲开码。

### 修复（已写入源码，**尚未烧录**）
- `AUTO_BOOT_GRACE_MS=15s`：上电宽限内禁止自动关  
- `gCloseArmed`：仅 **自动开成功** 或 **强→弱（确认进库后离开）** 后才允许自动关；库内唤醒丢包不再关  
- 经典状态机改为 **seen/rssi 边沿** 才评估  
- `default_rf_keys.h`：编入实车验证开 49p / 关 80p  
- 开机：key0/key1 无效或 **两者相同** → 写回默认开/关码  
- 新串口命令 `rfdefaults` 强制恢复默认码  

烧录后若开码仍不对，可在串口执行 `rfdefaults` 再 `rfplay 0`。
