# ESP32 硬件产品开发路线

> 从车库门项目 P0 实战复盘提炼。目标：**下一次做 ESP32 硬件产品，按阶段走、少踩坑。**  
> 日期：2026-09-28 · 关联：`docs/联调踩坑_PN532_NFC.md`、`docs/联调记录_20260919_RF学习与BLE自动门.md`

---

## 0. 核心原则

1. **风险先行**：先消灭会「烧板 / 堵死 / 砸车 / 双板不一致」的坑，再堆功能。
2. **硬件层站稳再写功能层**：外设失败可恢复、安全默认、多板一致，都属于地基。
3. **可观测性分两级**：最小版（版本号 + 日志规范 + 可刷回）跟骨架走；完整远程运维等金路径。
4. **金路径只有 1 条**：一条真实场景闭环跑通之前，不并行开第二条功能线。
5. **凡是对外有动作的**（RF / 继电器 / 关门指令），上电默认安全态，超时自动回安全态。

---

## 1. 阶段总览

```text
S0 骨架（1–2 天）
  ↓  版本号 / 日志规范 / 分区表 OTA 预留 / 一键烧录
S1 外设点亮（每个 0.5–2 天）
  ↓  一次一个 · 失败可恢复 · 独立诊断命令
S2 金路径 + 现场实测（3–5 天）
  ↓  一条用户价值最高的闭环 · 真实环境数据
S3 安全默认 + 状态机（2–3 天）
  ↓  危险功能上电关 · armed 条件 · 多板默认值
S4 完整远程运维（按需）
  ↓  公网 OTA · 心跳 · 日志上报 · 远程指令
S5 产品化
     配置 UI · 多设备一致性 · 商品文档 · 兼容表
```

**不要跳阶段。** 每个阶段有明确「可离开」条件（见 §3）。

---

## 2. 为什么是这个顺序（对照本项目弯路）

| 本项目弯路 | 根因 | 本应落在 |
|---|---|---|
| RF 学习被噪音判成功 | 无预热/无脉冲门槛/过早「成功」 | S2 |
| PN532 I2C SCL 锁死 | 失败路径不松总线 + 后台死循环 init | S1 |
| `rfauto` 整夜堵死门机接收 | 危险功能上电恢复 NVS、无会话超时 | S3 |
| 第二块板开码不对 | 默认码未写死进固件 | S3 |
| BLE 自动开被门磁误判 | 传感器真实行为未验证就写逻辑 | S2 |
| SoftAP「时有时无」 | 单射频互斥策略后补 | S1 / S4 |
| OTA 版本混乱、Update.begin 被碎片堆卡死 | 分区/版本/互斥后补 | S0 / S3 / S4 |
| 夜间异常只能事后猜 | 无远程日志 | S4（但 S0 要有串口规范） |

**结论**：完整 OTA/日志系统放最前会空转（给空壳装仪表）；但**不预留版本/分区/日志格式**，后面全是糊涂账。所以拆成 S0 最小可观测 + S4 完整运维。

## 3. 分阶段清单与「可离开」条件

### S0 · 骨架（1–2 天）

目标：工程能编、能刷、能区分版本、日志可 grep。

- [ ] PlatformIO / IDF 工程可重复编译（单命令 build + upload）
- [ ] **版本号自动生成**（如 `0.x.YYYYMMDDHHmm`，编译前写入头文件；禁止手写死）
- [ ] **分区表按 OTA 预留**：app0 / app1 + nvs（+ 纯数据分区按需）
- [ ] **串口日志规范**：统一 `[TAG]` 前缀（`[BOOT] [NFC] [RF] [FSM] [OTA] [HEAP] [WIFI]`），关键路径可 grep
- [ ] 一键烧录脚本（现场 30 秒能刷回）
- [ ] `pinmap.md`：电源 / 共地 / 上拉 / 电平 / GPIO 表；**禁止对调脚位写清楚**
- [ ] 看门狗与 `millis` 回绕约定（有符号差比较）
- [ ] 空闲堆基线打点（启动后 `[HEAP] free=...`）

**可离开条件**：改一行代码 → 自动升版本 → 一键刷入 → 串口能看到新版本与 `[BOOT]`。

---

### S1 · 外设点亮（每个 0.5–2 天）

目标：一次只加一个外设；合入主循环前必须过「三件套」。

**每个外设合入主循环前（缺一不可）**：

- [ ] 独立点亮 demo（可单独验证该外设）
- [ ] **失败路径可恢复**（`Wire.end` / 超时退出 / 状态复位）；禁止失败后后台死循环重试
- [ ] 独立串口诊断命令（`nfcinit` / `rfkeys` / `i2cscan` 这类）

**电气/驱动硬约束（常见坑）**：

- I2C：确认上拉；失败必 `Wire.end`；超时合理（如 200ms）；init 失败只允许手动重试
- RF 收发：TX 空闲拉低；看门狗防 DATA 卡高
- 继电器/强电：独立供电、共地；上电默认断开
- 单射频（WiFi + BT）：**先测互斥**，写「谁让谁」策略，不要等现象出来再猜

**可离开条件**：每个外设有诊断命令，断电/拔线/错误接线后能恢复，无「死锁只能整板断电」的路径。

---

### S2 · 金路径 + 现场实测（3–5 天）

目标：**只做一条**用户价值最高的闭环（本项目：学遥控码 → 发射开门），在真实环境验证。

- [ ] 金路径写成一句话，全队对齐（例：「按学习键 → 对码 → 手动开门成功」）
- [ ] 学习/抓包工具**抗噪**：预热丢起振、脉冲门槛、过滤过早「学习成功」
- [ ] **实车/实场验证**后才标记「已验证」；桌面数据不作数
- [ ] RSSI / 场强阈值**到现场测**（门挡、库内、门口分点）；写进 `config.h` 注明测量条件
- [ ] 传感器（门磁等）真实极性/抖动先用串口确认，再进逻辑
- [ ] 验证结果落盘：`tools/xxx_backup.json`、联调记录

**可离开条件**：金路径在目标场景连续成功 N 次（建议 ≥10）；关键阈值有现场数据支撑。

---

### S3 · 安全默认 + 状态机（2–3 天）

目标：自动逻辑只在「硬件可信」之上叠加；一切危险动作可自动回安全态。

**安全**：

- [ ] 危险功能（周期发射、自动关、继电器长吸合）**上电强制 OFF**，不恢复 NVS 会话
- [ ] 会话超时自动 OFF（如 `rfauto` 120s）
- [ ] TX / 外设看门狗（卡死强制拉安全态）
- [ ] **armed 条件**：仅「本系统确认已开/确认进库」才允许自动关，防连发
- [ ] 上电宽限期（boot grace）内禁止自动动作
- [ ] 冷却：开/关分别限频

**状态机**：

- [ ] 用边沿（无→有 / 强→弱）而不是电平轮询触发
- [ ] 拒绝时打日志（`[FSM] reject reason=...`），不要静默
- [ ] 关键阈值集中在一个配置头，注释写清物理含义

**多板一致**：

- [ ] 已验证的默认码/配置**编进固件**（`default_*.h`）
- [ ] 开机检测 NVS 异常（空 / 两 key 相同 / 长度错）→ 写回默认
- [ ] 串口命令可强制恢复默认（如 `rfdefaults`）
- [ ] 两块板烧同一固件后行为一致（抽查）

**可离开条件**：拔电重上、错误 NVS、射频干扰下，系统仍停在安全态；自动动作均有冷却与 armed 约束。

---

### S4 · 完整远程运维（按需，设备已装现场）

目标：人在电脑前能看见、能升级、能回看。

**建议实施顺序**（与 `docs/方案B_公网HTTP_OTA与心跳日志.md` 一致）：

1. 心跳 + 设备列表（先「看见」）
2. version.json + 固件下载 + 设备拉取升级（最小 OTA）
3. 日志 POST + 查询
4. 管理触发 / 灰度
5. 收紧鉴权与 HTTPS

**与硬件层的衔接（必做）**：

- [ ] 写 flash 期间暂停 NFC / Inquiry / 其它慢外设（避免 I2C 被拖死）
- [ ] 仅 STA 已连才上报/拉取；失败指数退避 + 本地环形缓冲
- [ ] OTA 与 BT/NFC 的资源互斥在 S3 定好，S4 只调用
- [ ] 层域网调试通道与公网通道可并存（USB/局域网仍可用）

**可离开条件**：远程能看到版本与日志；推送一次升级，现场设备无人干预完成并上报新版本。

---

### S5 · 产品化

- [ ] 配置向导（非工程师也能配）
- [ ] 多设备：同一固件、不同 NVS、行为可预期
- [ ] 安全说明（自动关保守策略、原遥控仍可用）
- [ ] 兼容表 / 学习失败兜底模式
- [ ] 商品文档与安装说明

---

## 4. 两条硬规矩（必须写进团队约定）

1. **外设合入主循环前，必须：点亮 demo + 失败恢复 + 诊断命令。三缺一不准合入。**
2. **对外有动作的功能，上电默认安全态 + 超时回安全态。**  
   教训来源：`rfauto` 写入 NVS 上电恢复 → 整夜每 5s 发开码 → 门机接收被堵 → 原遥控/刷卡全失效。

## 7. 快速检查：现在该不该进下一阶段？

| 问 | 否 → |
|---|---|
| 版本号能自动升、能远程/现场区分吗？ | 回 S0 |
| 每个外设失败都能恢复吗？有诊断命令吗？ | 回 S1 |
| 金路径在真实场景连续成功过吗？阈值现场测过吗？ | 回 S2 |
| 断电重上、坏 NVS、干扰下仍是安全态吗？ | 回 S3 |
| 人不在现场能看见版本/日志并升级吗？ | 做 S4 |
| 非工程师能配、多板行为一致吗？ | 做 S5 |

## 8. 一句话版

> **骨架留好 OTA 的位置，外设点亮带失败恢复，金路径现场验证，安全默认进固件，最后再装远程仪表。**  
> 最小可观测越早越好；完整运维等金路径。
